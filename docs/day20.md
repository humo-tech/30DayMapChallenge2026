# Day 20: Hexagons — 実装解説

ハローサイクリングのステーション 15,616 か所を [H3](https://h3geo.org/) のセルに集計し、光る六角柱として描く。カメラのズームに合わせて H3 の解像度が切り替わり、画面上のセルの大きさはほぼ一定に保たれる。2D（真上から見た平らなタイル）と 3D（ドック数に応じて伸びる柱）はボタンで切り替える。

| ファイル | 役割 |
|---|---|
| `public/data/day04/stations.geojson` | Day 4 と同じステーションの座標とドック数 |
| `app/maps/day20.vue` | ページ本体。ズームから解像度を決める、2D/3D の切り替え、冒頭のカメラ |
| `app/maps/lib/h3Cells.ts` | ステーション → H3 セルの集計、解像度の選択 |
| `app/maps/lib/HexPrismsMeshDesc.ts` | 六角柱と足元の光を描く自作の Navara 部品 |

## 1. H3 の使い方（`h3Cells.ts`）

[H3](https://h3geo.org/) は Uber の六角形の格子。地球を正二十面体に投影し、各面を六角形で敷き詰めている（全体で 12 個だけ五角形が混じる）。解像度 0〜15 があり、1 つ上がるごとにセルは約 1/7 の面積（辺は約 1/√7）になる。セルは `892f5a32d97ffff` のような 64 bit の ID（16 進文字列）で表す。

ブラウザで [h3-js](https://github.com/uber/h3-js)（v4）をそのまま使う。前処理のスクリプトはなく、ページを開いてから必要な解像度だけ集計する。使っている関数は 4 つ。

| 関数 | 使いどころ |
|---|---|
| `latLngToCell(lat, lng, res)` | ステーションの座標 → そのステーションが入るセルの ID |
| `cellToLatLng(id)` | セルの中心。柱の中心と、足元の光の位置に使う |
| `cellToBoundary(id)` | セルの輪郭の頂点。柱の上面と側面をこれで作る |
| `getHexagonEdgeLengthAvg(res, 'm')` | 解像度ごとの辺の平均の長さ。ズーム → 解像度の選択と、柱の高さの単位に使う |

h3-js は **`[lat, lng]` の順**で受け取り・返すので、Navara 側の `[lng, lat]` に入れ替えている（`cellToBoundary(id).map(([lat, lng]) => [lng, lat])`）。

集計（`buildCells(stations, res)`）:

1. 全ステーションを `latLngToCell` でセル ID にし、`Map<id, { capacity, count }>` にドック数と駅数を足し込む。ID が文字列なのでそのまま Map のキーになる。
2. セルごとに中心・輪郭・値を求める。値は `log1p(ドック数) / log1p(その解像度の最大)`。都心のセルが飛び抜けるので対数にしている。
3. `seed` はセル ID のハッシュ（FNV-1a 系）から作る 0〜1。ズームし直しても同じセルは同じ周期でまたたく。

`h3Cells.ts` は、解像度ごとの辺の長さを `EDGE_M` として最初に 1 回だけ表にしておく。今回使う範囲（3〜10）とデータ上の数:

| res | 辺の長さ | 面積 | セル数 | 最大ドック数 |
|---|---|---|---|---|
| 3 | 69 km | 12,393 km² | 30 | 66,920 |
| 4 | 26 km | 1,770 km² | 70 | 49,389 |
| 5 | 9.9 km | 253 km² | 160 | 16,943 |
| 6 | 3.7 km | 36 km² | 467 | 16,559 |
| 7 | 1.4 km | 5.2 km² | 1,737 | 9,192 |
| 8 | 531 m | 0.74 km² | 6,211 | 4,022 |
| 9 | 201 m | 0.11 km² | 12,354 | 2,007 |
| 10 | 76 m | 0.015 km² | 14,861 | 1,008 |

res 10 でもステーション 15,616 か所がほぼ別々のセルに分かれるので、それより細かくはしない。

### 輪郭は六角形とは限らない

`cellToBoundary` は正二十面体の辺をまたぐセルでは頂点が 7 つ以上になる。日本の上にも二十面体の辺が通っていて、res 3 で 3 セル、res 5 で 2 セルがそうなっている。五角形のセル（日本付近にはない）も含め、頂点の数を決め打ちせず `ring.length` で作っている。

## 2. ズームに合わせて H3 の解像度を変える

- Day 4 と同じ式で画面中央の 1px あたりの m（`metersPerPx`）を出し、`EDGE_PX`（22px）に一番近い辺の長さの解像度を選ぶ（3〜10）。
- H3 は解像度が 1 上がるごとに辺が約 √7 倍違うので、境目でちらつかないよう、今の解像度が最良より 0.25（対数）以内なら変えない。
- セルの集計は解像度ごとに初めて使うときに作ってキャッシュする（`setFor` → `buildCells`）。H3 の計算は res 10（約 15,000 セル）でも Node で 0.1 秒ほど。

## 3. 六角柱

GeoJSON にして Navara のレイヤーで押し出す（extrude）のではなく、Three.js のメッシュを自分で組み、高さは頂点シェーダーで決めている。

### 形を作る（JS、解像度が変わったときに 1 回）

- `cellToBoundary` の頂点を `geodeticToVector3` で ECEF（地球中心の 3D 座標）にし、中心に向かって `fill` 倍に縮める（セルの間に隙間ができる）。
- 1 セル = 上面（中心からの扇）+ 側面（辺ごとの四角形）。**頂点はすべて地面の高さに置いておく**。側面の上端も、この時点では下端と同じ位置にある。
- 1 解像度ぶんのセルを 1 つの `BufferGeometry` にまとめる（res 10 の約 15,000 セルでも描画 1 回）。位置はアンカーからの差分で持つ（float の精度のため。Day 4 と同じ理由）。
- 頂点ごとの属性:

| 属性 | 中身 |
|---|---|
| `position` | 地面の点（アンカーからの差分） |
| `aCenter` | セルの中心（同じ座標系） |
| `aInfo` | x: 上面 0 / 側面 1、y: 柱の足 0 / 頭 1、z: 上面の中心 0 / 縁 1 |
| `aVS` | セルの値（0〜1）と seed |

### 持ち上げる（頂点シェーダー、毎フレーム）

- 高さ = `mix(0.05, 0.5 + 6 × value^1.15, 2D/3D の割合) × 辺の長さ`。2D では薄いタイル、3D では柱。
- 上向きは `normalize(地面の点 + アンカー)`、つまり地球の中心から外向き。柱は地球の丸みに沿ってその場で真上に立つ。
- `aInfo.y = 1`（頭）の頂点だけをこの高さぶん持ち上げる。
- 2D/3D の割合は `uExtrude`（0〜1）。ビューの中心からの距離に応じて遅らせ、`easeOutBack` で行き過ぎてから落ち着かせるので、中心から外へ波のように立ち上がる。
- 解像度が変わると、新しいセルが中心から広がりながら湧き（seed でセルごとにずらす）、古いセルは縮んで消える（`uGrow` / `uLeaving`）。スロットを 2 つ持ち、表と裏を入れ替えている。
- 背の高いセルほど、外へ流れる波に合わせてわずかに伸び縮みする（呼吸）。

### なぜ GeoJSON + extrude にしないか

- 2D/3D の切り替え、立ち上がりの波、解像度の入れ替えを、**ジオメトリを作り直さず uniform を動かすだけ**で済ませたい。
- 上面と側面で光り方を変える、セルごとにまたたかせる、といった描き方には専用のシェーダーが要る。
- 自作の `ShaderMaterial` でも、`setupMaterialForMRT` で Navara の G-buffer に書けるようにすれば、選択ブルームが効く。

## 4. キラキラ

すべてフラグメントシェーダー。時計は 1 本。

- 法線は持たせず、画面上の微分（`cross(dFdx(pos), dFdy(pos))`）から面の向きを出す。面ごとに一様な陰影になり、柱の角がはっきりする。
- 色は インディゴ → 青 → シアン → マゼンタ → 金 → 白 のランプ。
- 上面は中心が明るく、縁に光る線が走る。縁の明るさは外へ広がる波で脈打つ。
- 側面は下が暗く、光の帯が柱を登っていく。上の縁は明るい。
- セルごとにランダムな周期でまたたき、白に近いフラッシュが出る（明るいセルほど強い）。
- 足元には加算合成の光だまり。値 0.3 以上のセルの中心に、地面に沿った正方形を 1 枚置き、シェーダーで円くぼかす（大きさは値に比例）。プリズムも光だまりも、色をそのまま発光バッファへ書くので、選択ブルームでにじむ。

## 5. 2D / 3D の切り替え

- 2D: 真上（俯角 90°、方位 0°）。3D: 俯角 52°、方位 20°。
- 今のカメラが地面を見ている点と距離を求め（平らな地面の近似）、同じ点を見たまま `flyTo` で俯角だけ変える。同時に `uExtrude` を 0↔1 で動かす。

## 6. 調整ポイント

`HexPrismsMeshDesc.ts`（`day20.vue` の `hexConfig` から渡す）:

| 設定 | 今の値（既定値） | 効果 |
|---|---|---|
| `fill` | 0.9 | セルの間の隙間（小さいほど広い） |
| `height` | 6 | 柱の高さ（辺の長さ単位、最大値） |
| `glow` | 0.3（0.7） | 足元の光の強さ |
| `sparkle` | 0.5（1） | またたきの強さ |
| `duration` | 800 ms | 解像度が変わるときの湧く・消える時間 |

`day20.vue`: `EDGE_PX`（セルの画面上の大きさ）、`selectiveBloom`（`strength` 0.5 / `radius` 0.4 / `threshold` 0.5）、`TILT_3D`、`MODE_MS`。

# Day 22: Projections — 実装解説

デザイナーが描いた「間引いてデフォルメした地図」に、緯度経度でピンを立てる。Natural Earth や OpenStreetMap の境界線をそのまま使うと細かすぎて美しくないことがある。そこでデザイナーは海岸線を丸め、小さな島を落とし、東京を大きくし、沖縄を枠に入れ、グリーンランドを縮める。こうして描いた地図には、緯度経度から位置を出す式がない。**式がないなら、対応点（タイポイント）から作る**。これを「フリーハンド図法（Freehand Projection）」と呼ぶことにした。

日本（都道府県）と世界（国）の 2 枚がある。もう 1 つのモード「Align a PDF」では、**デザイナーが Illustrator から書き出した PDF をアップロードして、その場で位置合わせ**できる（数点を手で対応付け → 輪郭を自動で合わせる → タイポイントを JSON で書き出し、ブラウザでも Python でもピンを置ける）。Navara は使わず、プレーンな SVG で描いている。

## 1. デザイナー役（`build_maps.py`）

本物のデザイナーの代わりに、スクリプトが地図を描く。**ページはこの曲げ方を知らない**。ページが受け取るのは SVG とタイポイントだけ。

### 実際の境界

- 日本：Overture Maps の `division_area`（`region` = 都道府県）。海に面した 39 都道府県は `maritime`（領海を含む）を、内陸の 8 県は `land` を使い、Day 1 の海岸線（Overture `base/land`）で切り抜く。Overture の `land` は北海道と沖縄だけ粗い（北海道全体で 910 点）ので、こうしている。県庁所在地は `division` の `capital_division_ids`。
- 世界：Natural Earth 1:50m の国境。首都は 1:10m の populated places の `Admin-0 capital`（202 都市）。南極と南ジョージア島は落とす。

### 曲げる（デザイナーの自由な手）

元の平面（日本はメルカトル、世界は 150°E を中心にした Natural Earth 図法）の上で、フレームごとに曲げる。

| 地図 | フレーム | 曲げ方 |
|---|---|---|
| 日本 | main | 東京のまわりを最大 2.15 倍、大阪のまわりを 1.7 倍に膨らませる（中心ほど大きく、縁で 1 倍に戻る。折れ返らない範囲） |
| | hokkaido | 津軽海峡の線より北。函館の沖を中心に 0.86 倍 |
| | okinawa / sakishima | 沖縄本島まわり、宮古・八重山をそれぞれ約 1.9 倍にして、九州の南の枠に入れる。奄美とトカラは元の位置のまま |
| | none | 三宅島より南の伊豆諸島、小笠原、大東、尖閣：描かない |
| 世界 | main | 日本を最大 2 倍、ヨーロッパを 1.55 倍、シンガポールのあたりを 1.6 倍に膨らませる |
| | greenland | 30°W の切れ目をまたぐので、まるごとアメリカ側に回し、ネアズ海峡を中心に 0.72 倍 |
| | none | 60°S より南：描かない |

### 間引いて丸める

1. 曲げたあと px に直し、小さな島（日本 10 px²、世界 14 px² 未満）を落とす。国ごと消えてしまう小国は点（円）にする。
2. `shapely.coverage_simplify` で間引く。隣どうしの境界は共有したまま。
3. 境界を「3 つ以上の領域が出会う点」で区切った弧に分け、弧ごとに Chaikin 法で 2 回角を落とす（端点は動かさないので隣とずれない）。`polygonize` で面に戻し、いちばん重なる都道府県・国に割り当てる。

### タイポイント

デザイナーが地図と一緒に渡すもの、という設定。「この実際の場所が、絵のこの点」。

- **境界が出会う点**（三県境、県境が海岸に出るところ）。間引いても丸めても動かないので、ぴったり合う。
- **輪郭に沿った点**。絵の輪郭の上に約 13 px おきに点を取り、いちばん近い実際の境界の点と組にする。間引きで消えた岬や湾は、ここで「絵ではこの辺り」と対応がつく。

日本 324 点、世界 739 点。スクリプトは自分でもスプラインを当てはめて確かめる。県庁所在地・首都が、曲げ方から直接出した位置とどれだけずれるかを見る。日本は中央値 0.4 px（最大 5 px）、世界は 0.1 px（最大 2 px）。

## 2. フリーハンド図法（`freehand.ts`）

### thin-plate spline

フレームごとに、タイポイントの「元の平面での位置 → 絵の上の位置」を thin-plate spline で結ぶ。

- `U(r) = r² log r` の重みとアフィン部分を、(n+3) 元の連立方程式で解く（部分ピボットのガウスの消去法。日本の main で n = 261、一瞬）。
- 正則化 λ = 1e-4。少しだけ緩めて、近すぎるタイポイントで波打たないようにしている。
- タイポイントの外では、だんだんアフィン変換になる。海の上もそれらしく続く。

元の平面を挟むのは、スプラインに任せる歪みを小さくするため。メルカトルなら日本の形はすでにほぼ合っていて、スプラインは膨らみと丸めの分だけ受け持てばよい。

### フレーム

緯度経度がどのフレームに入るかは、フレームの領域（緯度経度の多角形）で順に判定する。`none` に入れば「地図にない」。枠のないフレーム（main と hokkaido）は 1 枚のつながった絵を分け合っている。だから津軽海峡の線のところで経緯線が段違いになる。

### 逆変換（絵の点 → 緯度経度）

カーソルの下の緯度経度や、クリックした地点のために使う。

1. 点が枠の中なら、そのフレーム。外なら、枠のないフレームを順に試す。
2. 逆向きのスプライン（絵 → 元の平面）で初期値を出し、本来のスプラインでニュートン法を 8 回まで回す（ヤコビアンは数値微分）。
3. 元の平面から緯度経度に戻す。Natural Earth 図法の逆はニュートン法で緯度を求めてから経度を出す。
4. 地球の外（極の先、世界の端の外）に出た点や、戻したらフレームが違った点は捨てる。

### ピンを正しい県に置く

間引いた海岸線では、海沿いの都市（大津、ドーハ、ジブチなど）がスプラインの位置だとわずかに海に出ることがある。ピンの先がほんの少しだけ海に出ているのは見た目に落ち着かないので、そこだけ直す。

- ピンは、自分の属する都道府県・国（実際の境界の中にあるかで判定）を知っている。
- スプラインの位置がその領域の絵の外のとき、ピンが実際に立っている島（実際の境界の輪）の大きさで寄せ方を変える。面積が大きな島（日本は約 0.05 平方度 ≒ 600 km² 以上、世界は 0.5 平方度以上）なら 15 単位以内で、いちばん近い輪郭の点から 1 単位内側に寄せる。小さな島のピンは寄せない（絵の上で隣の大きな島のそばに落ちても、そちらには寄せない）。点（円）になった小国は 3 単位以内で点に寄せる。
- それより遠いもの（丸めて消えた湾の奥の町、描かなかった島、点になった小国から離れた首都）は、スプラインの位置のまま海に置く。

初めは 20 単位まで寄せていたが、小さな島や点になった小国の首都が遠くから陸に引き寄せられ、「目印に合わせて歪ませる」という図法の決まりから外れて不自然だったので、小さな島は寄せず、大きな島だけ寄せることにした。

「Ties」を表示すると、寄せたピンは元の位置から赤い線で結ばれる。

## 3. ページ（`day22.vue`）

- SVG は `fetch` して DOMParser で開き、中身をそのまま `v-html` で差し込む。デザイナーの絵には手を加えない。ピンを寄せるのに使う都道府県・国の輪郭は、`<path>` の `d`（M / L / Z だけ）から読む。
- その上に、すべて図法を通して重ねる：ピン、経緯線（日本 1°、世界 15°）、実際の境界（「Real borders」。細かい本物の線が、丸めた絵にどう乗るか見える）。経緯線と実際の境界は、初めて表示するときに一度だけ計算する。
- ピンは北から順に落ちてくる。画面上の大きさは一定（小さな画面では小さめ、ズームするとわずかに大きく）。
- ドラッグでパン、ホイール・ピンチでズーム。マウスなら、カーソルの下の緯度経度を左下に出し続ける。
- 「Where am I?」はブラウザの位置情報をそのまま図法に通し、県・国への寄せもする。

### 見比べる：左にフリーハンド、右に Web メルカトル

日本・世界のモードでは、画面の右半分（スマートフォンでは下）に同じ範囲の Web メルカトルの地図（MapLibre GL JS）を置いている。どちらの地図をクリックしても、その場所のピンが**両方に**立つ。

- 左（フリーハンド）をクリック：逆変換で緯度経度にして、右の地図のその緯度経度にピン。
- 右（Web メルカトル）をクリック：その緯度経度を図法に通し、左の地図にピン（県・国の絵の外にわずかに出たら寄せる）。左の地図にない場所（小笠原など）なら「off this map」と出す。
- ピンがもう一方の地図の画面の外なら、そこまで動かす。
- 右の地図にも県庁所在地・首都を赤い点で出す（ポインタを乗せると名前）。
- 右の地図には、左のフリーハンド図法が合わせている実際の都道府県境・国境（`japan.json` / `world.json` の `regions`）も線で重ねる。背景が明るい地図なら紺、Blue Marble なら白。
- 「Compare」を外すと右の地図を隠し、フリーハンドの地図が画面いっぱいになる。URL に `?compare=off` を付けると、最初から隠した状態で開く。同じように `?ties=on`、`?real=on` で「Ties」「Real borders」を最初からオンにできる（サムネイルは `?compare=off&ties=on&real=on` で撮る）。
- 世界は 150°E を中心にして左と揃える。Web メルカトルは画面の高さいっぱいに世界を描くので、縦長の画面では左右が少し切れる。

### ラスターを歪める：Blue Marble

「Blue Marble」を押すと、NASA の Blue Marble（陰影起伏・海底地形付き）をフリーハンド図法で歪めて、左の地図に重ねる。右の Web メルカトルの地図も同じ Blue Marble（GIBS のタイル）に替わる。「Land only」なら陸地の形で切り抜き、外せば海まで見せる。

- 元の画像（`fetch_blue_marble.py`）：NASA GIBS の WMS から等緯度経度で取る。日本は 121〜151°E・22〜47°N を 1° 100 px（3000 × 2500）。世界は 4096 × 2048 で、GIBS は全球を 1 枚では返してくれないので 90° ずつ 8 枚取ってつなぐ。
- **順向きのメッシュで歪める**（`warpRaster.ts`）。緯度経度の格子（日本 0.08°、世界 1°）の頂点をそれぞれ図法に通して絵の上に置き、格子のマス 1 つを三角形 2 つにして、元の画像をテクスチャとして貼る。逆変換（ニュートン法）は使わないので速い。WebGL2 で絵の 2.5 倍の大きさに一度だけ描き、画像にして SVG に入れる。
- 3 つの角が違うフレームに入るマスは描かない。だからフレームごとに別々に歪む（「Land only」を外すと、北海道や沖縄の枠の継ぎ目が見える）。地図に描かない範囲（伊豆諸島の南など）は空白になる。
- 世界の格子は 30°W から東へ 330° まで（切れ目から切れ目まで）。テクスチャは東西にくり返す。切れ目の上の列は左右の端に分かれて地図を横切る三角形になるので、辺が地図の幅の 1/4 より長い三角形は捨てる。
- 海岸線：デザイナーの絵は海岸線を丸めているので、画像の海岸とは数 px ずれる。ピンのように 1 点ずつ寄せることはできないので、「Land only」で絵の陸地の形に切り抜き、県境・国境の白い線を上に描き直す。
- **格子でも見られる**（「Grid 0.2°」「Grid 0.5°」）。`make_grid.py` が作る等緯度経度の格子の画像を同じように歪める。世界は 3600 × 1800（1° = 10 px）で 0.5° ごと、10° のマスを交互に塗り、10° ごとに緯度経度を書く。日本はそれでは粗いので、10800 幅（1° = 30 px）を基準にして日本の範囲（121〜151°E・22〜47°N、900 × 750）だけを切り出し、0.2° ごと、1° のマスを交互に塗り、2° ごとに緯度経度を書く。線は最も細かい間隔（薄い）・1°・5°（紺）・10°（赤）、赤道と本初子午線は太く。東京・大阪のまわりでマスが広がり、北海道や沖縄の枠の継ぎ目で線が段違いになるのが見える。右の Web メルカトルには同じ間隔の格子をベクターの線で引く（画像を Web メルカトルに貼ると緯度方向が合わないので）。細かい線と 1° の線は、間が詰まりすぎるズームでは消す。
- はまったところ：グリーンランドのように切れ目をまたぐフレームは経度を折り返さずにつないでいるが、格子は 180° を越えて（330° まで）走らせるので、285° のような経度がそのまま入ると 360° ずれた所に投影されていた。**図法に通す前に経度を -180〜180° に直す**ことにした（`freehand.py` と `build_maps.py` も同じ）。

## 4. PDF の位置合わせ（Align a PDF）

想定している流れ：デザイナーが Illustrator で地図を描き、PDF で書き出す → ページにドロップする → 位置合わせをして、タイポイントを JSON で書き出す → ブラウザ（`FreehandProjection`）でも Python（`freehand.py`）でも、その JSON で緯度経度を PDF 上の位置にできる。

### PDF を読む（`pdfArt.ts`、`pdfPaths.ts`）

- pdf.js で 1 ページ目を開く。「アート単位」はページを長辺 1600 に拡大した座標。画像は 2.5 倍の解像度で描き、拡大してもぼけにくくしている。
- **ベクターのパスも取り出す**。`getOperatorList()` の `constructPath` を読み、`save` / `restore` / `transform` / form XObject で変換行列を追って、ページ上の折れ線にする（ベジェ曲線は 8 分割）。描くたびに 1 つの「形」。クリップだけのパスと、ページ全体を覆う背景は捨てる。塗りと線で同じパスが 2 回出てくるものは 1 つにする。
- pdf.js（本体 0.47 MB とワーカー 1.27 MB）は Align モードを開いたときだけ読み込む。

### 手で対応付ける

左が実際の地図（日本はメルカトル、世界は 150°E か 0° を中心にした Natural Earth 図法）、右が PDF。PDF の上の点と、実際の地図の同じ場所を順にクリックすると、番号付きのタイポイントになる。

- 3 点で当てはめが始まる。6 点まではアフィン変換、それ以上は thin-plate spline（λ = 1e-2。手のクリックは数 px ずれるので、少し緩める）。
- 当てはめができると、実際の境界・県庁所在地（首都）・経緯線が PDF の上に重なる。ずれている所が見えるので、そこにタイポイントを足す。
- **パート**：枠に入れた沖縄や、縮めて動かしたグリーンランドのように、デザイナーが別に動かした部分。「Add a part」で PDF の上と実際の地図の上にそれぞれ矩形を引くと、別のフレームになる（矩形が枠として描かれている必要はない）。世界地図の切れ目（中心が 150°E なら 30°W）をまたぐパートは、経度を切れ目で折り返さずにつなげる。
- **タイポイントを直す**：番号の丸をどちらの地図でもドラッグして動かせる（押した所でつかむので、丸が指先に飛ばない）。動かしている間も当てはめを 1 フレームに 1 回やり直すので、重なった実際の境界やピンが追従し、合った所で離せばよい。選んだ点は矢印キーで 1 画面ピクセルずつ動く（⇧ で 10、⌥ / Alt で実際の地図の側）。
- タイポイントを選んで Delete で消す、⌘Z / Ctrl+Z で最後の 1 点を取り消す、Esc で打ちかけをやめる。
- 手のタイポイントを直しても自動のタイポイントはそのまま残るので、もう一度 Auto-fit すると作り直される。
- 「Export ties」で書き出す JSON には、手のタイポイント・自動のタイポイント・パートと、そのまま `FreehandProjection` に渡せるフレームが入っている。「Import ties」で読み戻して続きができる。

### 自動の当てはめ（`align.ts`）

手のタイポイントだけでは、デザイナーが大きくした所（東京、大阪）がずれたまま残る。そこで PDF の輪郭を実際の境界に合わせて、タイポイントを自動で増やす。ICP（iterative closest point）の一種で、9 回くり返す。

1. **形を見分ける**。いまの当てはめで実際の都道府県（国）を PDF の上に描き、PDF の形ごとに「形のうち、その県に入る割合」と「県のうち、その形に入る割合」を足したスコアを出す（2 倍に大きく描かれた東京でも、本物の東京がまるごと中に入るので高くなる）。スコアの高い組から、1 つの県に 1 つの形を割り当てる。島のような小さな形は、同じ県に重ねて割り当ててよい。
2. **境界が出会う点を対応付ける**。PDF の上でも実際の地図の上でも、隣り合う相手が変わる点（三県境、県境が海岸に出る所）を探す。PDF の点が「茨城・栃木・福島」なら、実際の地図の「茨城・栃木・福島」の点と組にする（同じ組み合わせが複数あれば近い方）。これは境界に沿って滑らない。
3. **輪郭に沿った点**。各形の輪郭の上に 3 単位おきに点を取り、その形と同じ県の実際の境界の、いちばん近い点と組にする。24 単位に 1 つに間引く。
4. 中央値の 2.5 倍より遠い組は捨て、当てはめ直す。届く距離は 40 → 5 単位、λ は 0.3 → 3e-3 と、粗く硬い当てはめから細かく柔らかい当てはめへ進める。

実際の境界のうち、湖（穴）と小さな島は使わない（デザイナーの地図にないので、近くの別の線に引っ張られる）。

うまくいかなかったことと、その理由：

| やり方 | 結果 |
|---|---|
| 輪郭の点を、どの県かを見ずにいちばん近い実際の線と組にする | 東京のまわりで当てはめが 25〜30 px ずれていると、県境どうしの間隔と同じくらいなので隣の県境に吸い付き、そのまま固まる |
| 県を見分けて、同じ県の境界と組にする | 隣の県境には行かなくなるが、東西に走る県境では東西のずれを直せない（境界に沿って滑る） |
| ＋ 境界が出会う点 | 滑りが止まる。輪郭の点を減らす（11 → 24 単位に 1 つ）とさらに良くなる |

見本の PDF（日本）で、正解（スクリプトが曲げた位置）と比べた県庁所在地のずれ（アート単位、長辺 1600）：

| | 中央値 | 90% | 最大 |
|---|---|---|---|
| 手のタイポイント 22 点（岬や湾） | 5.8 | 22 | 28 |
| ＋ 自動の当てはめ | 2.1 | 12 | 21 |
| 手を 25 点（関東・近畿の内陸に 3 点足す）＋ 自動 | 2.1 | 7.0 | 13 |

世界（手 20 点 ＋ グリーンランドのパート ＋ 自動）は中央値 1.3、90% 7.9。手の 3 点を足すと良くなる、というのが「半自動」の意味で、画面に重なる実際の境界を見ながらずれている所にタイポイントを足し、もう一度自動で合わせる。

### Python から（`freehand.py`）

書き出した JSON を読んで、ブラウザと同じ計算（基準の図法 → アフィンか thin-plate spline）をする。numpy だけで動く。ブラウザの結果との差は 1e-8 単位以下。

```bash
python scripts/day22/freehand.py map.freehand.json 139.767 35.681          # → x y（アート単位）
python scripts/day22/freehand.py map.freehand.json --csv places.csv --pt 1190.55   # name,lng,lat → PDF のポイントで
```

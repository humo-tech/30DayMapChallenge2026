# Day 13: Interactions — 実装解説

渋谷駅のまわりを歩いて、コーヒーショップに立ち寄るゲーム。Navara の地図の上で、矢印キーか WASD（タッチ画面ではドラッグ）で歩く。歩けるのは**道の上だけ**。コーヒーショップにはコーヒーのマークが立っていて、その店の前の道に立って店の方へ押し込むと中に入り、100 点もらえる。足元の矢印が、まだ入っていない一番近い店の方角を指す。

| ファイル | 役割 |
|---|---|
| `scripts/day13/extract_shibuya.py` | Overture Maps から、道（グラフ）・建物・コーヒーショップを切り出す |
| `public/data/day13/streets.json` | 交差点 2,865、道 4,092 本、線路（描くだけ） |
| `public/data/day13/buildings.geojson` | 建物 5,268 棟と高さ |
| `public/data/day13/coffee.json` | コーヒーショップ 284 軒 |
| `app/maps/day13.vue` | ページ本体。地図、入力、カメラ、店に入る流れ、建物の切り取り |
| `app/maps/lib/streetWalk.ts` | 道のグラフ、道の上だけを歩く人、店の入口 |
| `app/maps/lib/CoffeeWalkMeshDesc.ts` | 動くもの：歩く人、入口の目印、方角の矢印、湯気 |
| `app/maps/lib/coffeeMarks.ts` | コーヒーのマーク（Canvas で描いた PNG） |

```
Overture (S3) ─ extract_shibuya.py ─▶ streets.json / buildings.geojson / coffee.json
                                                 │ fetch
  毎フレーム（preUpdate）                          ▼
   ├─ 入力 → 画面の上 = カメラの向き → 地図上の向き
   ├─ 入口に押し込んでいる？ ─ yes → 店に入る（0.35 s）→ 得点・湯気・マークを済みに
   │                         └ no  → walk()：道に沿って進む
   ├─ CoffeeWalkMeshDesc：人・入口の目印・矢印・湯気
   ├─ カメラ：人を後ろ上から追う
   └─ カメラと人の間の建物を 1 階分まで沈める
```

## 1. データ：`extract_shibuya.py`

渋谷駅を中心に東西南北約 1.5 km の箱で、Overture の 3 つのテーマを DuckDB で S3 から直接読む。

**道**は `transportation/segment` の `road`。高速道路（首都高）と地下（`level` が負：駅のコンコースや地下鉄）は外す。Overture のセグメントは交差点をまたいで長く続くことがあるので、各セグメントが持つ `connectors`（交差点の ID と、線上の位置 `at`：0〜1）で切って、**交差点から次の交差点まで**を 1 本の辺にする。交差点の ID がそのままグラフの頂点になるので、立体交差（デッキや歩道橋）が平面上で重なっていても、つながっていない道どうしがつながることはない。最後に、一番大きく連結した部分だけを残す（どの道からもどの道へも行ける）。

**建物**は `buildings/building` の外形と高さ。高さがなければ階数 × 3.5 m、それもなければ 9 m。

**コーヒーショップ**は `places` の `coffee_shop`・`coffee_roastery` と、名前にコーヒー（coffee / 珈琲 / コーヒー / 喫茶 / カフェ…）を含む `cafe`。同じ名前で 12 m 以内のものは同じ店（ソース違いの重複）として 1 つにする。

## 2. 道の上だけを歩く：`streetWalk.ts`

座標は、箱の中心から東へ x m・北へ y m の平面。人の位置は「どの辺の、始点から何 m か」（`edge`, `s`）で持つので、**道から外れることがそもそもできない**。

入力は地図上の向き（単位ベクトル）。毎フレーム、進める距離ぶん次の規則で進む。

- **交差点**：つながっている辺それぞれの「出ていく向き」（交差点から 8 m 先の点への向き。交差点のすぐそばの折れ曲がりに惑わされないため）と入力の内積をとり、一番近い辺へ入る。キーは 4 方向か 8 方向しかないので、許す角度は広めの約 78°（内積 0.2）。どれもなければ、歩いている向きにまっすぐ続く辺（内積 0.7 以上）へ。それもなければ止まる。
- **曲がり角の手前**：道を横切る向きに押したとき、前後 20 m 以内の交差点で、交差点の規則がその入力で「別の道」を選ぶ（しかも内積 0.55 以上で、いまの道より 0.15 以上入力に近い）なら、その交差点へ向かう。角の少し手前でキーを押しても、止まった位置から押しても曲がれる。交差点と同じ選び方をするので、角で行ったり来たりしない。
- **辺の途中**：それ以外は、いまいる区間の向き `t` と入力の内積が ±0.5（60°）を超えれば、近い方へ進む。超えなくても、歩いている最中で入力が逆向きでなければそのまま進む（曲がった道を、キーを押し替えずに歩き通せる）。

全交差点の全ての曲がり方（6,857 通り）で、曲がりたい道の向きを 4 方向のキーに丸めて押したとき、その道に入れる割合は 86%（8 方向なら 97%、角の 6 m 手前で止まってから押しても 85%）。残りは、同じキーの向きに道が 2 本ある角。

辺の終わりや折れ点で 1 歩を区切るので、速く歩いても角を飛び越さない。乱数の入力で 20 km 以上歩かせて、位置が辺から外れないこと、1 フレームに進む距離を超えて跳ばないことを確かめた。

## 3. 店に入る

各店の**入口**は、店の位置から一番近い道の上の点（`doorsOf`）。入口から店への向きが「入る向き」。店が道の真上にあるときは、道を横切る向きならどちらからでも入れる。

入口から 7 m 以内で、入力が入る向きに 0.6（53°）以上向いていれば「押し込んでいる」。歩く処理より先に判定するので、道を歩きながら店の方へキーを押し替えるだけで止まって押し込める。0.18 s 押し続けると入る。

入る流れ（`day13.vue`）は、店の方へ 3 m 進みながら小さくなって消え（0.35 s）、その瞬間に得点・湯気・マークの切り替え・チャイム、少し中にいて（0.55 s）、入口に戻ってくる（0.35 s）。1 軒目を出てからは、コーヒーを手に持って歩く。ビルの中の店がいくつも同じ入口になることがあり、押し込むたびに次の店に入る。

## 4. 地図：Navara のレイヤー

背景はなく、楕円体の地面（`terrain: { ellipsoid }`）に `globe.color` でラテの泡の色を塗る。

- **道**：GeoJSON をその場で作って、地面に貼る折れ線（`clampToGround`）。歩道・階段・横断歩道のレイヤーの上に、縁取り → 車道の順に重ねる。幅は画面上の px なので、ズームが落ち着いたらカメラの距離に合わせて評価し直す。
- **建物**：押し出した多角形。色は高さの対数で、低いほど淡く、高いほど深煎り。光は環境光と朝 9 時半の太陽。
- **コーヒーのマーク**：ビルボード。`depthTest: false` でビルに隠れない。入った店は、評価関数が返す画像（`image`）を「済み」のマークに替えて `forceUpdate()`。

## 5. 動くもの：`CoffeeWalkMeshDesc.ts`

自作のメッシュ記述子。箱の中心に `geodetic` で置き、中の Three.js のオブジェクトを東・北の m で毎フレーム動かす。

- **歩く人**：カプセルと球で組んだ人。歩いた距離で脚と腕を振る。等身大だとカメラから見えないので、カメラの距離に比例して大きくする。
- **透けて見える影**：ビルの陰に入っても見えるよう、人を包むカプセルを `depthFunc: GreaterDepth`（何かの奥にあるところだけ描く）で重ねる。人の形をそのまま複製すると、髪が頭の「手前」にあるせいで頭に色が乗るので、自分を隠さない凸形にした。
- **入口の目印**：28 m 以内の入口に輪と、店の方へ流れる山形。近いほど濃い。
- **矢印**：まだ入っていない一番近い入口の方角。入口が近くにあるときは目印に任せて消える。
- **湯気**：入った瞬間に入口から広がる輪と、立ちのぼる粒。

## 6. カメラと建物の切り取り

カメラは Navara の操作を切って（`enableSpin / Tilt / Zoom: false`）、毎フレーム `setCamera({ distance, heading, pitch })` で人を後ろ上から追う。向きは Q / E かマウスのドラッグ、距離はホイール。入力の「上」は常にカメラの向く方なので、カメラを回しても操作は画面どおり。

渋谷スクランブルスクエア（約 230 m）のような高層ビルがあると、カメラがビルの中に入ったり、人が隠れたりする。そこで、**カメラと人の間に立つ建物を 1 階分（4 m）まで沈める**。建物ごとに重心と半径を持っておき、人からカメラへの帯（建物の半径 + 8 m の幅）に入っていて、そこでの視線の高さより高ければ「邪魔」。毎秒 15 回判定して、0.3 s かけて沈む（評価関数の `extrudedHeight`）。

ただし、帯の縁の建物は歩くたびに入ったり出たりするので、そのままだと上下にベコベコする。そこで**ヒステリシス**を付ける。一度沈んだ建物は、帯の幅を 4 倍（半径 + 32 m）にして判定し、そこから外れても 3 s は沈んだまま、それから 0.8 s かけてゆっくり伸びる。同じ道順を歩いて、沈み始めてから伸びかけてまた沈む「折り返し」は 14 回から 3 回に減った（残りは道を引き返したときの正当なもの）。

# Day 13: Interactions — 実装解説

渋谷駅のまわりを歩いて、コーヒーショップに立ち寄るゲーム。Navara の地図の上で、矢印キーか WASD（タッチ画面ではドラッグ）で歩く。歩けるのは**道の上だけ**。コーヒーショップにはコーヒーのマークが立っていて、その店の前の道に立って店の方へ押し込むと中に入り、100 点もらえる。足元の矢印が、まだ入っていない一番近い店の方角を指す。

| ファイル | 役割 |
|---|---|
| `scripts/day13/extract_shibuya.py` | Overture Maps から、道（グラフ）・建物・コーヒーショップを切り出す |
| `public/data/day13/streets.json` | 交差点 2,865、道 4,092 本、線路 21 本（描くだけ）。0.53 MB |
| `public/data/day13/buildings.geojson` | 建物 5,268 棟と高さ。1.28 MB |
| `public/data/day13/coffee.json` | コーヒーショップ 284 軒。0.02 MB |
| `app/maps/day13.vue` | ページ本体。地図、入力、カメラ、店に入る流れ、建物の切り取り、得点 |
| `app/maps/lib/streetWalk.ts` | 道のグラフ、道の上だけを歩く人、店の入口（描画に依存しない純粋な計算） |
| `app/maps/lib/CoffeeWalkMeshDesc.ts` | 動くもの：歩く人、入口の目印、方角の矢印、湯気 |
| `app/maps/lib/coffeeMarks.ts` | コーヒーのマーク（Canvas で描いた PNG） |

```
Overture (S3) ─ extract_shibuya.py ─▶ streets.json / buildings.geojson / coffee.json
                                                 │ fetch（3 つ同時に、view.init() と並行）
                                                 ▼
  起動時   buildGraph()（m の平面のグラフ） / doorsOf()（店ごとの入口）
           Navara のレイヤー：地面・道・線路・建物・コーヒーのマーク
           CoffeeWalkMeshDesc（動くもの）

  毎フレーム（preUpdate）
   ├─ 入力（キー / スティック）→ 画面の上 = カメラの向き → 地図上の向き
   ├─ 店に入っている途中？ ─ yes → 入る / 中にいる / 出てくる
   │       └ no → 入口に押し込んでいる？ ─ yes → 0.18 s で入り始める
   │                                    └ no  → walk()：道に沿って進む
   ├─ CoffeeWalkMeshDesc：人・入口の目印・矢印・湯気
   ├─ カメラ：人を後ろ上から追う（setCamera）
   ├─ カメラと人の間の建物を 1 階分まで沈める（毎秒 15 回）
   └─ ズームが落ち着いたら道の幅を評価し直す
  毎フレーム（preRender）
   └─ 「+100」と店名を、入った店の上に浮かべる
```

## 1. データ：`extract_shibuya.py`

渋谷駅を中心にした箱（経度 139.6935〜139.7105、緯度 35.6505〜35.6655。東西 1.54 km、南北 1.66 km）で、Overture（リリース 2026-10-21.0）の 3 つのテーマを DuckDB で S3 から直接読む。`bbox` 列で絞るので、Parquet の大半の行グループは読まずに済み、全体で 1〜2 分。

```bash
scripts/.venv/bin/python scripts/day13/extract_shibuya.py   # --release 2026-10-21.0 --out DIR
```

### 道：交差点で切ったグラフ

`transportation/segment` のうち `road` を、箱より少し（0.002°、約 200 m）広めに読む。箱の縁をまたぐ道を途中で切らないため。外すのは次の 2 つ。

- **高速道路**（`class = motorway`）：渋谷の上を通る首都高 3 号線。人は歩けない。
- **地下**（`level_rules` に負の値）：駅のコンコースと地下鉄。地上の道と重なって描かれ、どこから地下へ降りたのか分からなくなるので、地上だけにした。

Overture のセグメントは、交差点をまたいで長く続くことがある。各セグメントは `connectors`（交差点の ID と、線上の位置 `at`：0〜1）を持っているので、`at` で線を切って（`cut()`）、**交差点から次の交差点まで**を 1 本の辺にする。切る位置は線の長さ（m）で割り振り、間の頂点はそのまま残す。

交差点の ID がそのままグラフの頂点になるので、立体交差（駅前のデッキや歩道橋）が平面上で重なっていても、つながっていない道どうしがつながることはない。逆に、長さ 0.05 m 未満の辺は「同じ点に 2 つの交差点 ID がある」だけなので、両端を 1 つの交差点にまとめる（Union-Find）。

箱の中に 1 点もかからない辺は捨て、最後に**一番大きく連結した部分だけを残す**。これで、どの道からもどの道へも行ける（離れ小島に閉じ込められない）。

`streets.json` の形：

```jsonc
{
  "bbox": { "xmin": 139.6935, "xmax": 139.7105, "ymin": 35.6505, "ymax": 35.6655 },
  "nodes": [[lng, lat], ...],                     // 交差点
  "edges": [{ "a": 0, "b": 1, "class": "footway", // 両端の交差点と、道の種類
              "line": [[lng, lat], ...] }, ...],  // 交差点から交差点までの線
  "rails": [[[lng, lat], ...], ...]               // 線路（描くだけ）
}
```

`class` は `subclass` があればそちら（`sidewalk`・`crosswalk`・`alley`・`link` など）。座標は小数 6 桁（約 0.1 m）に丸め、丸めて重なった点は落とす。

### 建物

`buildings/building` の外形と高さ（`is_underground` は除く）。高さがなければ階数 × 3.5 m、それもなければ 9 m。外形は全部 `MultiPolygon` にそろえて、プロパティは高さ `h` だけ。

### コーヒーショップ

`places` のうち、次のどちらか（営業中、確からしさ `confidence` 0.5 以上、箱の中）。

- `taxonomy.primary` が `coffee_shop` か `coffee_roastery`。
- `cafe` で、名前に coffee / espresso / roast / 珈琲 / コーヒー / 喫茶 / カフェ を含む。日本の「カフェ」はケーキ屋やバーのこともあるので、名前で絞る。

同じ名前で 12 m 以内のものは、ソース違いの重複として 1 つにする（確からしさの高い方を残す）。

## 2. グラフ：`buildGraph()`

座標は、箱の中心から東へ x m・北へ y m の平面にする。1.5 km 四方なので、経度 1° = 111,320 m × cos(緯度)、緯度 1° = 110,950 m の正距円筒で十分（端での誤差は数 cm）。

| 持つもの | 中身 |
|---|---|
| `nodes[i]` | 交差点の位置 |
| `edges[e]` | 両端 `a`・`b`、種類、線の頂点 `pts`、始点から各頂点までの距離 `cum`、長さ `length` |
| `at[i]` | 交差点 `i` につながる辺の一覧 |

辺の両端の頂点は、交差点の位置にぴったり合わせ直す。丸めのずれで、交差点を通るときに人が小さく跳ばないように。

## 3. 道の上だけを歩く：`walk()`

人の位置は「どの辺の、始点から何 m か」（`edge`, `s`）で持つ。だから**道から外れることがそもそもできない**。ほかに、辺のどちら向きに歩いているか（`moving`：+1 / −1 / 0）と、向いている方（`facing`）。

入力は地図上の向き（単位ベクトル）。毎フレーム、進める距離（速さ × 経過時間）を、次の規則で使い切るまで進む。

- **交差点**：つながっている辺それぞれの「出ていく向き」と入力の内積をとり、一番近い辺へ入る。出ていく向きは、交差点から 8 m 先の点への向き。交差点のすぐそばの折れ曲がりに惑わされないため。キーは 4 方向か 8 方向しかないので、許す角度は広めの約 78°（内積 0.2）。どれもなければ、歩いている向きにまっすぐ続く辺（内積 0.7 以上）へ。それもなければ止まる。
- **曲がり角の手前**（`turnAhead()`）：道を横切る向きに押したとき、前後 20 m 以内の交差点で、交差点の規則がその入力で「別の道」を選ぶなら、その交差点へ向かう。ただし、その道が内積 0.55 以上で入力に向いていて、いまの道より 0.15 以上入力に近いときだけ。これで、角の少し手前でキーを押しても、止まった位置から押しても曲がれる。両方の交差点が条件を満たせば、歩いている先の方、止まっていれば近い方。交差点とまったく同じ選び方をするので、交差点に着いたとたん別の道を選んで引き返す（角で行ったり来たりする）ことがない。
- **辺の途中**：それ以外は、いまいる区間の向き `t` と入力の内積が ±0.5（60°）を超えれば、近い方へ進む。超えなくても、歩いている最中で、入力が逆向き（内積 −0.2 未満）でなければそのまま進む。曲がった道を、キーを押し替えずに歩き通せる。

1 歩は辺の終わりか線の折れ点で区切り、残りの距離で次の判定をやり直す。速く歩いても角を飛び越さないし、曲がった道でも線の上をなぞる。

### 確かめたこと

- **曲がれる割合**：全交差点の全ての曲がり方（6,857 通り）で、曲がりたい道の向きをキーの方向に丸めて押したとき、その道に入れた割合。残りは、同じキーの向きに道が 2 本ある角（どちらか一方にしか入れない）。

  | 押し方 | 入れた割合 |
  |---|---|
  | 4 方向のキーで、角に着いたとき | 86% |
  | 8 方向（斜めの同時押し）で、角に着いたとき | 97% |
  | 4 方向のキーで、角の 6 m 手前で止まってから | 85% |

  角の判定を広げる前（60°、手前の判定なし）は、それぞれ 69%・83%・49% だった。

- **壊れないこと**：乱数の入力で 20 km 以上歩かせて、位置が辺から外れないこと、1 フレームに進む距離を超えて跳ばないこと、無限ループにならないこと。

## 4. 入力

| 入力 | 動き |
|---|---|
| 矢印キー / WASD | 歩く（同時押しで斜め） |
| Shift | 急ぐ（16 → 32 m/s） |
| Q / E | カメラを左右に回す（90°/s） |
| マウスのドラッグ | 横でカメラを回す、縦で見下ろす角度（−88°〜−22°） |
| ホイール | カメラの距離（50〜480 m） |
| タッチのドラッグ | 指を置いた所がスティックの中心。14 px 以上動かした向きに歩く |

キーの向きは**画面に対して**：上は常にカメラの向く方。カメラの向き h（北から時計回り）のとき、画面の「上」は地図で (sin h, cos h)、「右」は (cos h, −sin h)。カメラを回しても、操作は見たとおりになる。

Navara のカメラ操作は切ってある（`camera.options = { enableSpin, enableTilt, enableZoom: false }`）。ドラッグで地図がずれると、歩く人が画面から外れてしまうため。

タッチ画面では、指を置いた所に輪とつまみ（スティック）を出す。`touch-action: none` でページのスクロールを止め、Pointer Events で指を 1 本だけ追う。

## 5. 店に入る

### 入口

各店の**入口**は、店の位置から一番近い道の上の点（`doorsOf()`）。全部の辺の全部の区間に点から垂線を下ろして、一番近いところ。入口から店への向きが「入る向き」。店が道から 1.5 m 以内（道の真上）にあるときは向きがないので、道を横切る向きならどちらからでも入れる。

284 軒すべて、入口は店から 40 m 以内。駅ビルの中の店は、いくつかが同じ入口を持つ（同じ点に最大 2 軒）。

### 押し込み

入口から 7 m 以内で、入力が入る向きに 0.6（53°）以上向いていれば「押し込んでいる」（`doorPushed()`）。候補が複数あれば、一番まっすぐ押している店。まだ入っていない店だけが候補。

この判定は歩く処理より**先に**する。道を歩きながら店の方へキーを押し替えるだけで、その場で止まって押し込める。0.18 s 押し続けると入る。すべての店に、押し込んで入れることを確かめた。

### 入る流れ

| 時間 | 起きること |
|---|---|
| 0〜0.35 s | 店の方へ 3 m 進みながら、小さくなって消える |
| 0.35 s | 得点（+100）、湯気、マークを「済み」に、チャイム、「+100」と店名 |
| 0.35〜0.9 s | 中にいる（姿は見えない） |
| 0.9〜1.25 s | 入口に戻ってくる（店に背を向けて）。手にはコーヒー |

入っている間は入力を受け付けない。出てきた人は、入口のある道の上に立っている。1 軒目を出てからは、ずっとテイクアウトのカップを手に持って歩く。

## 6. 地図：Navara のレイヤー

背景のタイルはなく、楕円体の地面（`addLayer({ type: 'terrain', ellipsoid: {} })`）に `globe.color` でラテの泡の色を塗る。光は環境光（1.1）と太陽（1.6）。太陽の向きは `atmosphere.date` で決まり、2026-11-13 の朝 9 時半（JST）にしてある。南東の低い太陽で、建物の東と南の面が明るい。

### 色：ラテ

| 名前 | 色 | 使う所 |
|---|---|---|
| `SKY` | `#f4ece1` | 背景（ズームアウトで箱の外に見える） |
| `GROUND` | `#e6d8c4` | 地面（泡） |
| `STREET` / `CASING` | `#fffcf6` / `#cdb59a` | 車道とその縁取り（ミルク） |
| `PATH` / `STEPS` | `#f6ead9` / `#a88466` | 歩道 / 階段 |
| `RAIL` | `#8d7766` | 線路（破線） |
| `BUILDING_LOW` → `BUILDING_HIGH` | `#e2cfb6` → `#8a6248` | 建物（浅煎り → 深煎り） |

### 道

辺から GeoJSON をその場で作り、地面に貼る折れ線（`clampToGround`）にする。描く順（後ほど上）は次のとおり。

1. **歩道**（`footway`・`sidewalk`・`crosswalk`・`steps`・`path`・`cycleway`）。横断歩道は白い破線（ゼブラ）、階段は茶色の点線。
2. **車道の縁取り**（車道の幅 + 4 px）。
3. **車道**。
4. **線路**。

幅は画面上の px（Navara の折れ線の幅）。種類ごとの幅（開始時の距離 170 m で）は、幹線 26・主要 24・二次 22・三次 18・生活道路 13・路地 8・歩道 6 px など。px なので、そのままではズームしても太さが変わらない。そこでホイールを止めて 0.25 s たったら、170 m ÷ いまの距離（0.35〜2.5 倍）を掛けて評価し直す（`forceUpdate()`）。毎フレームではないのは、地面に貼る線はタイルに焼き直すので重いから。

### 建物

押し出した多角形。高さ h で色を決める：`smooth(log2(h / 6) / 5)` で浅煎りから深煎りへ。6 m 以下はいちばん淡く、192 m 以上はいちばん深い。対数なので、低い建物の多い路地裏にも濃淡が出る。

GeoJSON はファイルの URL ではなく、一度 `fetch` してから `data` で渡す。各建物に通し番号 `i` を振って、重心と半径を先に計算しておくため（§8 の切り取りで使う）。評価関数は番号だけを読み（`filters: ['i']`）、高さと色は手元の配列から引く。

### コーヒーのマーク

`coffeeMarks.ts` が Canvas に描いて PNG にする（96 × 116 px）。ピンの頭に、ソーサーに乗ったカップと 3 本の湯気。入った店は、深煎りのピンにクリーム色のカップ、緑のチェック。

ビルボードで、画面上 36 px、ピンの先が店の位置（`anchor: 'bottom'`）。`depthTest: false` でビルに隠れず、`declutter: false` で重なっても全部出す。入った店の画像は、評価関数が返す `image` で切り替える（`visited` に入っていれば「済み」）。入るたびに `forceUpdate()`。

## 7. 動くもの：`CoffeeWalkMeshDesc.ts`

自作のメッシュ記述子（`MeshDesc`）。箱の中心に `geodetic` で置く。中の座標は西・上・北（Navara の `geodetic` の枠）なので、東・北の m を `(−x, 高さ, y)` に置き換えて、Three.js のオブジェクトを毎フレーム動かす。マテリアルは `MeshLambertMaterial`（光が当たる）と `MeshBasicMaterial`（目印など、光に関係なく同じ色）。

- **歩く人**：カプセルと球で組んだ 1.7 m の人。赤いセーター、紺のズボン。歩いた距離で脚と腕を振り、体が少し弾む。止まると振りがすっと収まる。等身大だとカメラから見えないので、カメラの距離 ÷ 22 倍にする（170 m で約 8 倍、上限 12 倍）。
- **コーヒー**：1 軒目を出てから、右手にスリーブ付きのテイクアウトカップ。持つ腕は前に上げて、振りは小さく。
- **透けて見える影**：ビルの陰に入っても見えるよう、人を包むカプセルを `depthFunc: GreaterDepth`（何かの奥にあるところだけ描く）で重ねる。人の形をそのまま複製すると、髪が頭の「手前」にあるせいで頭に色が乗る。そこで、自分を隠さない凸形（カプセル 1 つ）にした。
- **入口の目印**：まだ入っていない店の入口で、28 m 以内のもの（近い順に 6 つまで）。入口に輪と、店の方へ流れる 3 つの山形。7 m 以内（押し込める距離）でいちばん濃く、離れるほど薄い。ビルに隠れないよう、深度テストなしで描く。
- **矢印**：まだ入っていない一番近い入口の方角。人の足元の少し前の地面に。入口が 28 m 以内にあるときは目印に任せて消える。
- **湯気**：入った瞬間に、入口から広がるオレンジの輪と、立ちのぼる 8 つの粒（1.1 s）。4 つまで同時に。

## 8. カメラと建物の切り取り

カメラは毎フレーム `setCamera({ lng, lat, distance, heading, pitch })` で、人を後ろ上から追う（`distance` は見る点からの距離）。見る点は人の位置に指数的に追いつく（毎秒 6 の割合）。急に曲がってもカメラが揺れない。最初は北向き、見下ろし 52°、距離 170 m。カメラの高さは約 134 m。

### 建物を沈める

渋谷スクランブルスクエア（約 230 m）やヒカリエ（約 180 m）のような高層ビルがあると、カメラがビルの中に入ったり、人が隠れたりする。そこで、**カメラと人の間に立つ建物を 1 階分（4 m）まで沈める**。

建物は外形を、重心 c と半径 r の円で近似しておく。カメラまでの水平距離を D、カメラの高さを H とする。人からカメラの方へ向かう軸で、建物の重心が軸に沿って `along`、軸から横に `across` 離れているとき、次の 2 つを満たせば「邪魔」。

```
−r/2 < along < D + r   かつ   across < r + 8 m        … 人とカメラの間の帯に入っている
h > (along − r) / D × H − 8 m                          … そこでの視線の高さより高い
```

毎秒 15 回判定して、邪魔なら 0.3 s かけて沈む（評価関数の `extrudedHeight` を、元の高さと 4 m の間で補間）。人より向こうにある建物は沈まない。

### ベコベコしないように

帯の縁の建物は、歩くたびに帯に入ったり出たりする。そのままだと上下にベコベコする。そこで**ヒステリシス**を付けた。

- 一度沈み始めた建物は、帯の幅を 4 倍（半径 + 32 m）にして判定する。少し外れたくらいでは「邪魔」のまま。
- 帯から外れても、3 s は沈んだまま。
- それから 0.8 s かけてゆっくり伸びる（沈むのは 0.3 s）。

同じ道順（引き返しやカメラの回転を含む約 20 s）を歩いて、沈み始めてから伸びかけてまた沈む「折り返し」を数えると、14 回から 3 回に減った。残りは道を引き返したときの、正当なもの。

### 半透明にしなかった理由

邪魔な建物を半透明にする方法もあるが、ここでは沈める方にした。

- カメラの高さ（約 134 m）より高いビルが多く、カメラがビルの中に入る。半透明でも画面の大部分にビルの色がかかって、道が見づらい。
- 建物ごとに透明度を変えるには、建物レイヤー全体を半透明（`transparent`）にする必要がある。5,268 棟すべてが半透明の描画になり、面の重なりで濃さが足される（`depthPrePass` が要る）。手前と奥の順番も崩れうる。

## 9. ページ：`day13.vue`

- **最初の位置**：スクランブル交差点の真ん中。指定した点から 40 m 以内で、いちばん多くの道が集まる交差点（`startAt()`）に立たせる。
- **得点**：右上に、入った店の数 / 全店数と、得点（1 軒 100 点）。再読み込みすると 0 から。
- **「+100」**：入った入口の 60 px 上に、得点と店名の DOM 要素を出し、1.6 s かけて 50 px 浮かびながら消す。位置は毎フレーム `geodeticToVector3` → カメラで投影（`preRender`）。
- **チャイム**：Web Audio で、ソ（784 Hz）とレ（1,175 Hz）のサイン波を 0.09 s ずらして鳴らす。ブラウザは操作の後でないと音を出させないが、入るのはいつもキーかタッチの後なので問題ない。
- **操作の案内**：画面下に、キー（タッチ画面ではドラッグ）の使い方を 1 行。1 軒目に入ると 2 s 後に消える。
- **スマートフォン**：幅 600 px 以下では、ページのヘッダーが上を占めるので、得点は左下、操作の案内はその上に移す。
- **出典**：Overture Maps Foundation と OpenStreetMap contributors（Navara の出典表示に追加）。

## 11. 限界

- **地面は平ら**：地形はなく、道も建物も高さ 0 から。渋谷は「谷」で道玄坂も宮益坂も坂だが、坂は出てこない。
- **立体交差も平らに描く**：デッキや歩道橋（`level` が正）は地面に描かれる。グラフとしては正しくつながっているが、見た目には交差点でないところで向きを変えるように見えることがある。
- **地下は歩けない**：駅のコンコースや地下街は外した。地下の店の入口は、真上に近い地上の道になる。
- **入口は推定**：店の位置から一番近い道。実際の入口と違う道（ビルの裏側の路地など）になることがある。Overture の店の位置そのものが、ビルの中心に寄っていることも多い。
- **店のデータ**：Overture の `places` に基づく。閉店した店や、コーヒーを出さない「カフェ」が残っていることも、逆に名前に手がかりのない店が漏れていることもある。
- **角の店**：入口の判定を曲がる判定より先にしているので、角に入口がある店の方へ押すと、曲がる代わりにその店に入る（入っていない店だけ）。
- **同じ向きの 2 本の道**：キーの同じ向きに道が 2 本ある角では、入力に近い方にしか入れない（4 方向で 14%）。カメラを回すと、もう一方にも入れる。
- **切り取りは円で近似**：建物を重心と半径の円で見ているので、細長い建物は実際より広く「邪魔」とみなされ、早めに沈む。
- **道の太さ**：ズームしている最中は太さが変わらず、止めて 0.25 s 後に合う。
- **箱の外は何もない**：引いて見ると、1.5 km 四方の外は地面の色だけ。
- **記録は残らない**：入った店と得点は、ページを離れると消える。

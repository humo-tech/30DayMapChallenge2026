# Day 15: Inside out — 実装解説

Day 10 のパステルなぬいぐるみの原宿（Overture Maps の PMTiles を MapLibre で描いたもの）を Navara に置き換え、そこから「何かがおかしい」世界にする。アリスの世界。

- **ページ全体が歪む**：パネルも含めたページ全体が、池の水面のようにうねり、ゆっくり傾く。世界が裏返る間は、さらに強くうねる。
- **溶ける時計**：ダリの時計のようにだらりと垂れた時計が街の上に浮かぶ。針は逆回りで、速さもバラバラ。
- **鏡**：右下に金の枠の姿見。映っているのは、いまの地図を左右反転して色を変え、波打たせたもの。押すと鏡の向こう（世界が裏返る場面）に入る。
- **空から吊るされた街**：同じ街がもう 1 つ、屋根を下にして空からぶら下がっている。カメラが空へ落ちながらぐるりと回ると、吊るされた街が足を下にして立ち、本物の街が頭上にぶら下がる。このとき画面の上のパネルも逆さになる。
- **鏡文字**：画面の下に『鏡の国のアリス』の一節が鏡文字で出る。

操作：地図を触るとツアーが止まる（「Play tour」で戻る）。「Steady」でうねりと傾きを止められる（OS の「視差効果を減らす」でも止まる）。`?t=<秒>` でツアーのその時点から始まる。

| ファイル | 役割 |

## 1. PMTiles が重い問題

Day 10 では、Navara で Overture の PMTiles を読むと重すぎて MapLibre に逃げた。測ってみると、重さの正体は 2 つだった。

1. **タイルそのものが大きい**。東京の z14 のタイルは、1 テーマ 1 MB 前後（道の 1 タイルが gzip で 1.3 MB）。これは Overture の各地物が、出典・名前・通行規則など数十の属性を持っているから。デコードしてみると、1 タイルの道 4,251 本のほとんどのバイトが属性だった。
2. **使う範囲より広く読む**。Overture のアーカイブは世界全体で、ピラミッドの上の方（z12 など）のタイルも、東京なら 1 枚 1 MB 近い。Navara は `minZoom` を指定しても読むタイルが減らなかった（`minZoom: 12` にすると WebAssembly の panic で止まる）。

Day 10 の MapLibre 版は、同じ原宿で **64 MB**、Navara にそのまま PMTiles の URL を渡すと建物だけで **16 MB** 読んだ。

そこで、`extract_harajuku.py` で自前の PMTiles を作る。

- Overture の S3 から Range リクエストで、原宿の周り（z14 の 3×3 タイル、地面は z13 の 2×2）だけを読む。
- MVT をデコードして、スタイルが読む属性だけに削る。道は `class` と `subtype`、地面と水は `subtype`、建物は高さ（`height`、なければ階数×3.2 m、なければ 8 m）と、`id` の先頭 1 桁から決めた色番号だけ。地下の建物は捨てる。
- 道と建物は同じ z14 のタイルなので、2 つの MVT をバイト列のまま連結して 1 つのタイルにする（protobuf は連結すると両方のレイヤーが入った 1 つのメッセージになる）。
- 結果は 2 ファイル合わせて **1.5 MB**。Navara は、いま見えているタイルだけを Range リクエストで読む。

## 2. 地図の層

Navara の `vector-tile` ソース（URL が `.pmtiles` で終わると PMTiles として読まれる）に、層を重ねる。各地物の色や幅は、`featureUpdated` のイベントで属性から決める。

| 層 | 描き方 |
|---|---|
| 地面（`land`）、土地利用（`land_use`） | `subtype` ごとのパステル色のポリゴンを地面に貼る |
| 水（`water`） | 水色のポリゴン |
| 道（`segment`） | ピンクのふち、薄紫の布、大きな道には黄色の点線（ステッチ）。歩道・階段などは描かない |
| 線路 | ピンクの線に白の破線（キャンディストライプ） |
| 建物（`building`） | 8 色のお菓子の色。`h` の高さまで押し出す |

## 3. 空から吊るされた街

同じ建物をもう 1 つのレイヤーにして、高さの範囲を `[CEILING − h, CEILING]`（`CEILING` は 900 m）にする。つまり屋根が下、1 階が空に貼り付く。空の色は背景なので、ピンクの空から建物が生えているように見える。

## 4. ツアー

カメラは原宿の周りを回る。キーフレーム（方位・距離・高さ・ピッチ・ロール）の間を、Day 14 と同じ Catmull-Rom のエルミート補間でなめらかにつなぐ。

| 秒 | 場面 |
|---|---|
| 0〜38 | 街を見下ろしながら回る |
| 38〜58 | 空を見上げながらロールが 0° → 180°。ページがいちばん強くうねる |
| 58〜94 | 上下が逆さまのまま、吊るされた街（足を下にして立って見える）の周りを回る。パネルも逆さ |
| 94〜110 | ロールが 180° → 360° で元に戻る |

## 5. ページの歪み

SVG フィルターを `.map-page`（地図もパネルも入っている枠）に `filter: url(#…)` でかける。

- `feTurbulence`（ゆっくり動くノイズ）を `feDisplacementMap` に入れ、画面のピクセルをずらす。ノイズの周波数は、約 20 fps で少しずつ変える。ずらす量は、通常 26 px、世界が裏返る間は最大 86 px（スマホは 14〜44 px）。
- CSS の `transform`（スケール 1.05、回転、`skew`）を 17 秒周期でゆっくり動かす。端がフィルターで欠けるのを、拡大で隠す。
- パネルは歪みで端が切れないよう、少し内側に寄せる。

フィルターは毎フレームかかるので、重い端末では「Steady」で止められる。

## 6. 溶ける時計

`MeltingClocksMeshDesc` は、時計 7 個を 1 つのメッシュにまとめる。

- 時計は 36×36 分割の板で、文字盤（円、縁、ステッチ、12 の目盛り、時針・分針・秒針）はフラグメントシェーダーが板の `uv` 上に描く。
- 頂点シェーダーが板の下の方を下に伸ばし（中央ほど長く、伸び縮みする）、横と奥行きに波を走らせる。文字盤は `uv` 上に描いてあるので、板と一緒に垂れて歪む。
- 針は `uPace`（1 分あたりの回転数、負なら逆回り）で、時計ごとに違う速さで回る。
- 毎フレーム、各時計はカメラの方を向き（鉛直軸まわり）、浮き沈みする。

## 7. 鏡

画面右下の `<canvas>` に、Navara の描画の中央 80% を毎フレーム（約 20 fps）左右反転して描き写す（`drawImage`）。CSS の `hue-rotate` で色を回し、SVG の `feTurbulence` + `feDisplacementMap` で水面のように波打たせ、金の枠（`conic-gradient`）と反射のハイライトを重ねる。押すとツアーが 40 秒目（裏返る場面）へ飛ぶ。

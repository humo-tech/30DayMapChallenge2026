# Day 12: Power — 実装解説

世界の海の波を、ECMWF の波浪モデルのデータから Navara の地球儀の上に描く。色は波が運ぶエネルギーの量（**波パワー**）で、凪の紺から嵐の下の白まで、強いほど明るい。見せ方は右上のボタンで 2 通りに切り替えられる。

- **Fluid（粘体）**：Navier–Stokes 方程式を解く流体シミュレーション。波の流れに乗って、波パワーの色のインクが流れ、渦に混ぜられ、水面のように陰影が付く。
- **Streamlines（流線）**：波の峰を表す粒子が波の進む向きに走り、エネルギーの航跡を残す。

計算はほぼすべて GPU（WebGL2 のフラグメントシェーダー）で行い、CPU は毎フレーム描画の命令を出すだけ。どちらの見せ方も「いま見えている範囲」だけを計算するので、拡大するとその縮尺で細かく描き直される。

| ファイル | 役割 |
|---|---|
| `scripts/day12/fetch_waves.py` | ECMWF のオープンデータから波高・波向・周期を取り、float16 のバイナリにする |
| `public/data/day12/waves.bin` / `waves.json` | 0.25° 格子 1440×721 の 3 変数（6.2MB、gzip で 2.4MB）と、その説明 |
| `app/maps/day12.vue` | ページ本体。地球儀、モード切り替え、毎フレームの呼び出し |
| `app/maps/lib/waveField.ts` | 両モードの共通部分。波データの補間、見えている範囲の追従、海を覆うシェル |
| `app/maps/lib/WaveFluidMeshDesc.ts` | 粘体モード（Stable Fluids） |
| `app/maps/lib/WaveStreamMeshDesc.ts` | 流線モード（粒子と航跡） |

```
data.ecmwf.int ─ fetch_waves.py ─▶ waves.bin (float16) ─ fetch ─▶ day12.vue
                                                                  │ RGBA16F テクスチャ（1 回だけ）
  毎フレーム（preUpdate）                                           ▼
   └─ step(dt, カメラ) ─▶ WaveDomainMeshDesc（waveField.ts）
                           ├─ 見えている範囲 → 四角を決める（外れたら写し替え）
                           ├─ simulate()  … WaveFluidMeshDesc / WaveStreamMeshDesc
                           └─ シェル（地球を覆う面）に結果を貼る
```

## 1. 波のデータ：`fetch_waves.py`

ECMWF は IFS の波浪モデル（ECWAM）の予報を、0.25° の全球格子でオープンデータ（CC BY 4.0）として出している。1 回の予報ファイルには多数の変数が入っているが、使うのは次の 3 つだけ。

| 変数 | 意味 | 単位 |
|---|---|---|
| `swh` | 有義波高（風浪とうねりを合わせた波の高さ） | m |
| `mwd` | 平均波向。波が**来る**方角で、北から時計回り | ° |
| `mwp` | 平均周期 | s |

ファイルごとに `.index`（1 行 1 変数の JSON。バイト位置と長さが入っている）があるので、それを読んで 3 変数のぶんだけ HTTP の Range で取る（各 0.4〜0.5MB）。GRIB2 は eccodes で解く。

書き出し方：

- 行は北（90°N）から南へ、各行は 180°W から東へ。3 変数をセルごとに並べる（swh, mwd, mwp, swh, …）。
- **float16** にする。float32 だと 12.5MB になるため。WebGL2 は半精度のテクスチャを標準で読めるので、ブラウザ側で変換せずにそのまま GPU に上げられる。
- 陸と海氷は、3 変数とも **−1** にする。NaN はシェーダーの中で確実には判定できない（最適化で比較が消えることがある）ため。

`--date` を省くと、`.index` が既に出ている最新の 00z / 12z の予報を探す。今入っているのは 2026-11-12 00 UTC の解析値（予報 0 時間目）。

## 2. GPU に上げる：ピンポンと補間

### Transform Feedback ではなくピンポン

WebGL2 で GPU に計算させる方法は 2 つある。

- **Transform Feedback**：頂点シェーダーの出力をバッファに書き戻す。粒子のように、1 つずつ独立に更新するものに向く。
- **ピンポン**：テクスチャ A を読んでテクスチャ B に書き、次のフレームで入れ替える。上下左右の隣を読む計算（圧力や渦度）や、少し上流の位置を補間して読む計算（移流）に向く。

流体の計算はほとんどが隣を読む処理なので、ピンポンにした。流線の粒子は Transform Feedback でも書けるが、three.js は Transform Feedback を API として持っておらず、生の WebGL を呼ぶと three.js / Navara が管理している状態とぶつかるおそれがある。そこで粒子もピンポン（状態をテクスチャに持つ）にそろえた。

### 波データのテクスチャ

`waves.bin` は 3 チャンネルの半精度だが、RGB16F はブラウザによってはテクスチャを作れなかった（`glTexStorage2D` が失敗する）。そこで RGBA16F に詰め替えて上げる（`fieldUniforms()`）。フィルタは Nearest で、補間はシェーダーで自分で行う。

### `wave()`：周りの 4 セルから線形補間

格子は約 25km 間隔で、画面の 1 ピクセルよりずっと粗い。すべてのシェーダーは、ある点の波を `wave(経度緯度)` で読む。

1. 点を囲む 4 セルを `texelFetch` で読む。
2. 陸のセル（波高 < 0）は除き、残ったセルの重みで割り直す。海岸近くで、陸の 0 に引きずられて波が消えないようにするため。
3. **波向はベクトルにしてから**補間する。角度のまま平均すると、350° と 10° の平均が 180° になってしまうため。`mwd` は波が来る方角なので、進む向きはその逆にする。

返すのは次の 5 つ。

| 値 | 意味 |
|---|---|
| `dir` | 波が進む向き（東・北成分、長さ 1） |
| `steady` | 4 セルの向きがどれだけ揃っているか。1 なら同じ向き、0 なら逆向きの波がぶつかっている |
| `height` / `period` | 波高と周期 |
| `sea` | 海の割合。0 が陸、1 が外洋 |

## 3. 見えている範囲だけを計算する：`waveField.ts`

最初の版は、全球を 1 枚の正距円筒テクスチャ（4096×2048、約 10km/px）で計算していた。これだと拡大したときにテクスチャが引き伸ばされてぼやける。そこで、いま見えている範囲を正方形に切り出し、その中だけを計算するようにした。

### 四角（ドメイン）

視点の中心を中心にした**正射図法**で切り出す。正射図法は、遠くから地球儀を見たときの見え方そのものなので、地球全体が見えているときにも無理がない。四角は `[中心の経度, 中心の緯度, 半辺の長さ（地球半径単位）]` の 3 つの値で表し、シェーダーには `uDomain` として渡す。`toDomain()` / `fromDomain()` が、経度緯度と四角の中の座標（0〜1）を行き来する。

### 四角の決め方：`viewDomain()`

画面を 5×5 の点でサンプルし、各点から視線を延ばして地球（球）と交わる位置を求める。地球を外れた視線は、その方向の地平線（地球の、視線に最も近い点）を代わりに使う。画面中央の交点を中心にして、すべての点を収める大きさを半辺にし、それに 1.3 倍（`MARGIN`）の余裕を足す。

### 四角を取り直すとき：`needsNewDomain()`

毎フレーム次の 2 つを調べ、どちらかに当たれば新しい四角を取る。

- 見えている点のどれかが、今の四角の外（端から 2% 以内も含む）か、地球の裏側に出た。
- 大きく寄った。必要な大きさが今の四角の 0.6 倍を下回った。より細かい四角に取り直す。

### 写し替え（`carry`）

新しい四角の各ピクセルについて、そこが古い四角のどこに当たるかを求め、古いテクスチャから読む（`resampleFragment`）。速度のようなベクトルは、そのまま読むと向きがずれる。四角が変わると、四角の上での東と北の向きも変わるためだ。そこで、古い四角の上で少し進めた点を経度緯度に戻し、新しい四角に投影し直して、向きを新しい四角の軸に合わせる。

寄っていくと、古い（粗い）内容が引き伸ばされて写るが、計算がその縮尺の細かさで描き直していくので、数秒で細部が戻る。

### シェル（海を覆う面）

結果は、地球を覆う経度緯度の格子メッシュ（720×360 分割、楕円体から 3km 上）に貼る。フラグメントシェーダーが、自分の経度緯度から四角の中の位置を求めてテクスチャを読む。陸と、四角の外にあたる部分は描かない。

Navara の ECEF 座標の軸の向きは WASM の中にあって外から読めない。そこで `geodeticToVector3` に (0°, 0°)、(90°E, 0°)、(0°, 90°N) を渡して基底ベクトルを取り出し、それを使って格子を組んでいる（`ellipsoidGrid()`）。軸の向きがどうなっていても合う。

ブルームは Day 11 の `ThunderMeshDesc` と同じく、`USE_SELECTIVE_EFFECT` を立てて `setupMaterialForMRT` を通している。

### 共通の基底クラス `WaveDomainMeshDesc`

毎フレームの流れは基底クラスにまとめてある。各モードは次の 3 つを実装するだけでよい。

| フック | いつ |
|---|---|
| `begin()` | 最初、またはモードを切り替えた直後。テクスチャを空にする |
| `carry(from, to)` | 四角を取り直したとき。状態を新しい四角に写す |
| `simulate(dt, 四角)` | 毎フレーム。シェルに渡す uniform を返す |

## 4. 速さ：位相速度と群速度

深海の波は、峰が**位相速度** c = gT/2π で進む。一方、エネルギーはその半分の**群速度**で伝わる。周期 10 秒の波なら、峰は約 15.6m/s、エネルギーは約 7.8m/s。

この速さを実際の時間で動かすと地図の上ではほとんど動かないので、四角に対する割合で決めている。周期 10 秒の波の峰が、毎秒四角の `PHASE_SPEED`（5%）だけ進む。周期に比例して速くなる。四角に対する割合なので、どのズームでも画面の上では同じ速さに見える。

- 流線の粒子（峰）は位相速度で進む。
- 流線の航跡と、粘体のインク（どちらもエネルギー）は群速度で進む。

両モードとも同じ関数（`travelChunk` の `travel()`）を使っているので、流れの向きと速さは一致する。

## 5. 流線：`WaveStreamMeshDesc.ts`

### 峰（粒子）

384×384 = 約 15 万個。状態（経度、緯度、年齢、寿命）を RGBA32F のテクスチャに 1 ピクセル 1 粒子で持ち、ピンポンで更新する。

- 波の向きに位相速度で進む。中点法（半歩進んだ位置の向きで 1 歩進む）なので、うねりの曲がりに沿って曲がる。
- 寿命（2.5〜7 秒）が来たら、四角の中のどこかで生まれ直す。陸や四角の外、地球の外で生まれたら、次のフレームでやり直す。
- 逆向きの波がぶつかる場所（`steady < 0.3`）では消える。そこに粒子が溜まって線になるのを防ぐため。

### 航跡

四角の上の 1 チャンネルの半精度テクスチャ（2048×2048、地球全体が見えるときのためにミップマップ付き）。毎フレーム、

1. 各ピクセルが、群速度で 1 歩上流の位置の値を読む（移流）。同時に 1.6 秒で 1/e になるペースで薄れる。
2. 峰を点（1.5px）として加算で描き込む。頂点シェーダーが `gl_VertexID` から自分の粒子のピクセルを探して読む。明るさは波高に応じ、生まれたときと消えるときはフェードする。

峰は自分のエネルギー（群速度、半分の速さ）より先に進むので、後ろに航跡が伸び、それが流れに沿って曲がり、引き伸ばされる。

シェルは、航跡の濃さに波パワーの色を掛け、その下にパワーの分布を薄く敷く。

## 6. 粘体：`WaveFluidMeshDesc.ts`

### Stable Fluids

Jos Stam の Stable Fluids を、[WebGL Fluid Simulation](https://github.com/PavelDoGreat/WebGL-Fluid-Simulation) と同じ手順で、四角の上で解く。速度・圧力は 256×256、インクは 1280×1280 の半精度テクスチャ。

毎フレームの処理：

| パス | 内容 |
|---|---|
| `mean` | 波の流れ（下記）を計算する |
| `force` | 乱れを、かき混ぜの力に向けて引き寄せる |
| `curl` → `vorticity` | 渦度を求め、渦度強調で小さな渦を強める |
| `divergence` → `pressure` ×20 → `gradient` | 圧力を解いて、乱れを非圧縮にする |
| `advect`（速度） | 乱れを、波の流れ＋乱れで運ぶ |
| `advect`（インク） | インクを、波の流れ＋乱れで運ぶ |
| `inject` | インクを足す |

### 流れを 2 つに分ける

普通の流体シミュレーションは、速度場全体を圧力で非圧縮（湧き出しも吸い込みもない）にする。しかし波の場は、もともと湧き出しの多い場だ。

- 嵐の中心から、うねりが四方へ広がる（湧き出し）。
- 2 つのうねりがぶつかる線に集まる（吸い込み）。

速度場全体を非圧縮にすると、この成分が消され、データとは違う流れになる（流線とまったく違って見えた）。そこで速度を 2 つに分けた。

- **波の流れ**（`mean`）：データの向きと群速度から毎フレーム計算するだけで、圧力では消さない。逆向きの波がぶつかる場所（`steady` が小さい）では弱める。
- **乱れ**（`velocity`）：その上に乗る渦。ここだけを非圧縮で解く。

インクと乱れは、2 つを足した流れで運ぶ。乱れは発散がなく平均するとゼロなので、強くしてもインクを混ぜるだけで、全体の流れの向きは変えない。

### かき混ぜの力

乱れの元は、地球に固定したノイズの回転（curl noise）。回転なので発散を持たない。強さは波高に比例する（8m の海で最大）ので、荒れた海ほど激しく渦を巻く。

ノイズの模様の大きさは四角の大きさに合わせる。2 倍ずつ違う 2 つの縮尺を、四角の大きさに応じてクロスフェードしているので、四角を取り直しても模様が跳ばない。

時間で模様を変えるときは、**ずらさずにその場で変える**。無関係なノイズ 2 枚を時間でクロスフェードし（`morph()`）、混ぜた途中でコントラストが落ちないよう分散を補正する。最初は模様を球の z 軸（南北軸）方向にずらしていたが、これだと模様が地表を北から南へ掃いていき、インクが南へ「ブワーッ」と流れて見えた。

### インクの足し方

海のどこでも、その場所の波パワーの色に向けて、毎秒約 35%（`RELAX`）のペースで少しずつ近づける。ゆっくりなので、色が決まりきる前に流れがインクを遠くまで運ぶ。インクを別に減衰させる処理はなく、この近づけ方が古いインクを薄める役も兼ねる。

一様に足すと、インクがどこでも同じ濃さになり、渦が混ぜても模様ができない。そこで、地球に固定した大きめの斑（時間で一切変わらない）の中では、少し濃く足す。煙突から出る煙のように、濃いところから下流へ帯が伸び、それを渦が揺らす。

### 水面の陰影

インクの明るさを高さとみなし、2.5 ピクセル離れた点との差から法線を作る。左上からの光で拡散光と照り返しを付けると、流れながら波打つ面に見える。

## 7. 色：波パワー

色は**波パワー**、つまり波の峰 1m あたりが運ぶエネルギーの流量。

P = ρg² / 64π · Hs² · T ≈ 0.49 · Hs² · T [kW/m]（Hs：有義波高 m、T：周期 s）

ECMWF の `mwp` は、エネルギー周期に相当する周期なので、この式にそのまま使える。今のデータでは、中央値が約 20kW/m、上位 10% が約 80kW/m、上位 1% が約 180kW/m で、最大はアリューシャン列島の南の嵐で約 810kW/m（波高 11.9m）。

0〜600kW/m を対数スケールにして、**明るさが一方向に上がる**配色にしている（`rampChunk()`）。紺 → 青 → シアン → 淡い水色 → 白に近い灰白で、最上位だけごくわずかに暖かい。最初は青からオレンジへ変わる配色だったが、シアンとアンバーは明るさがほぼ同じで、量の大小ではなく「2 種類の海」に見えた。上端を純白にしないのは、ブルームで持ち上がって白く飛ぶため。

なお、流れの速さは**周期だけ**で決まり、色（パワー）は**波高の 2 乗**が効く。なので、速く流れる場所が明るいとは限らない。遠くから届いた長周期のうねりは、速いが低いので暗い。嵐の真下の荒れた海は、周期がそこそこでも高いので明るい。

## 8. ページ：`day12.vue`

- 最初のカメラは北太平洋の真上 11,000km。日本からアリューシャンの南の嵐までが入る。
- 地図は Day 11 と同じ暗いラスタータイル（papers-dark）を、灰青に染めて陸の形だけを見せる。地球の縁の光（`LimbGlowMeshDesc`）と星空（`StarfieldMeshDesc`）は Day 1 と同じ。
- 両モードのメッシュを両方追加しておき、表示しているほうだけ `step()` を呼ぶ。切り替えると、そのモードは `reset()` で空から始まり、数秒で埋まる。
- **寄りすぎの制限**：高度 300km より下には行かせない。Navara 0.3.1 のカメラの `minimumZoomDistance` は、ホイールでのズームを止めなかった。そこで毎フレーム高度を見て、下回っていたら押し戻している。

## 10. 限界

- 波のデータは約 25km の格子。拡大したときに見える細かい渦やうねりは、見た目のための演出（かき混ぜの力と渦度強調）で、データにはない。流れの向き・速さ・色はデータに従う。
- データは 1 時刻だけ（予報 0 時間目）。時間変化はない。
- 四角を頻繁に取り直す（地球を回し続ける、など）と、写し替えのたびに少しぼやける。数秒で戻る。
- 北極の付近は、背景のラスタータイル（Web メルカトルで約 85° まで）が届かず黒い円が出る。海氷の部分は波のデータもない。
